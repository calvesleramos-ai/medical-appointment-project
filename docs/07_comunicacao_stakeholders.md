# Comunicação aos Stakeholders

## Atualização do Projeto — Aplicativo de Agendamento de Consultas Médicas

## Contexto Atual

O projeto de desenvolvimento do aplicativo móvel para agendamento de consultas médicas encontra-se em uma fase intermediária de execução.

Até o momento, funcionalidades importantes como cadastro de usuários, gestão de agenda médica e fluxo inicial de agendamento estão em desenvolvimento.

Durante as últimas semanas, foram identificados alguns pontos de atenção que podem impactar o cronograma e a previsibilidade das próximas entregas.

---

# Principais Pontos de Atenção

## Integração com o Sistema de Prontuário

A integração com o sistema externo de prontuário apresentou instabilidades devido à ausência de documentação completa da API e alterações recentes realizadas pelo fornecedor.

Esse ponto possui alta prioridade, pois a integração é considerada crítica para a entrega final do produto.

## Alterações nos Requisitos

Foram solicitadas novas regras de negócio relacionadas ao fluxo de agendamento.

As alterações são importantes para garantir que o sistema atenda às necessidades dos usuários, porém precisam ser avaliadas para evitar impactos não planejados no prazo e no esforço da equipe.

## Capacidade da Equipe

A equipe atual é composta por quatro desenvolvedores e um tester.

O aumento de demandas nas últimas semanas gerou uma elevação da carga de trabalho, sendo necessário revisar prioridades e organizar melhor a distribuição das atividades.

---

# Riscos Identificados

Os principais riscos monitorados atualmente são:

- Atrasos relacionados à integração com o sistema externo.
- Impactos no cronograma devido às mudanças de requisitos.
- Redução da qualidade das entregas devido à sobrecarga da equipe.
- Dependência de sistemas externos para conclusão do projeto.

---

# Ações em Andamento

Para reduzir os impactos identificados, as seguintes ações estão sendo realizadas:

- Criação de uma estratégia de testes utilizando ambientes simulados quando necessário.
- Solicitação de documentação atualizada da API ao fornecedor.
- Priorização das funcionalidades mais críticas para a entrega.
- Revisão do backlog junto aos stakeholders.
- Maior acompanhamento dos testes durante o desenvolvimento.

---

# Próximos Passos

As próximas ações planejadas são:

1. Estabilizar a comunicação com o fornecedor do sistema externo.
2. Validar e priorizar as novas solicitações de requisitos.
3. Ajustar o planejamento das próximas entregas considerando a capacidade da equipe.
4. Realizar testes integrados antes da fase de homologação.
5. Monitorar continuamente os riscos identificados.

---

# Decisões Necessárias dos Stakeholders

Para garantir o sucesso do projeto, é necessário o alinhamento dos stakeholders sobre:

- Prioridade das novas funcionalidades solicitadas.
- Aceitação de possíveis ajustes no cronograma caso necessário.
- Disponibilidade das áreas envolvidas para validações e homologações.

---

# Conclusão

Apesar dos desafios identificados, o projeto permanece em andamento.

As ações definidas têm como objetivo reduzir riscos, aumentar a previsibilidade das entregas e garantir que o produto final atenda às necessidades dos usuários e do negócio.

O acompanhamento contínuo dos riscos e a comunicação transparente entre as equipes serão fundamentais para o sucesso da iniciativa.
